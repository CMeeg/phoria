## Global Constraints

- Commit messages and prose in British English; Biome formatting (tabs, no trailing commas, line width 120).
- Example refs must stay on **published** registry ranges — `pnpm examples:check` fails on `link:`/`file:` phoria refs or a Phoria `ProjectReference`.
- Companion `node_modules` and `.vite-config` output are git-ignored; never force-add them.
- Example scripts run from `WebApp/` (or `apps/WebApp/` for `with-workspace`); Vite resolves config from `process.cwd()`.
- Every example keeps its committed lockfile in sync with its `package.json` (no uncommitted lockfile drift).
- Phases 0–4 complete; this branch must land on **canary**, not `main`. The `@phoria/opentelemetry` package must have been published for standalone giget installs to resolve.
- Port map is collision-free (catalog: getting-started 5373/5273, framework-multiple 5573/5473, framework-react 5173/5073, framework-svelte 5473/5373, framework-vue 5273/5173, with-tailwind 5773/5673, with-styled-components 5873/5773, with-storybook 5973/5873, with-workspace 5673/5573).

## Review Focus

The input classes the parity spec implies but no task's tests exercise, that are most likely to bite a person using the examples:

1. **Missing dev dependency after plugin removal** — any example whose `vite.config.ts` still imports `@meeg/vite-plugin-inspect-config` after its `package.json` dep is removed, or vice versa. Expected: both are removed together in every single-WebApp example and a fresh `pnpm install` resolves cleanly (Task 1 Step 4 grep pin).
2. **A committed example that no longer builds standalone** — the whole point of the examples is giget-fetch → `pnpm install && pnpm build`. Expected: every example builds from a clean fetch of committed registry refs (Task 5 Step 8).
3. **Lockfile drift silently committed** — removing a dependency in 8+ examples must not leave `pnpm-lock.yaml` files describing the old dep set. Expected: `git status` shows only intended lockfile changes and they are committed with the `package.json` change (Task 1 Steps 2–4, Task 5 Step 6 reversibility).
4. **Allow-list selection has no effect or fails silently** — a typo'd `EXAMPLES_E2E` name must fail fast before any stack starts, and a valid subset must run only those examples. Expected: both behaviours observed (Task 5 Steps 3–4).
5. **Storybook build regresses on unpinned Vite** — `with-storybook` must stay on `~8.0.16` until the Rolldown regression is fixed; a later dependency bump must not silently ship the unpinned range. Expected: `build:storybook` succeeds on the pinned range (Task 5 Step 5).

## Risks and Mitigations

- **Low — inspect-config removal:** nothing in `scripts/` or `.github/` references the plugin (verified); it was the Vite 6→8 diff-baseline tool and is vestigial in examples. Mitigation: Task 1 Step 4 grep + `examples:check`.
- **Medium — giget fetches resolve latest published ranges:** the release-sync PR keeps examples current, so standalone fetches are most meaningful against post-sync state. Mitigation: Task 5 Step 8 records which examples need the beta publish rather than failing the phase on it.
- **Time — the unrestricted nine-example e2e is the longest run in the matrix:** the allow-list run (Task 5 Step 4) is the CI gate; the unrestricted run is due diligence. Mitigation: order the matrix cheap-first, and if e2e infrastructure is unavailable in the execution environment, record it explicitly in Task 5 Step 9 rather than silently skipping.
- **Low — plan-checkbox sweep is a mechanical edit with a review signal:** a ticked task whose verification is missing is the failure mode the sweep exists to prevent. Mitigation: Task 4 ticks only after Tasks 1–3 and 5 verify, never before.
